# Redstone Mod Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `redstone` Weft mod described in the design: predictable, order-independent signals; wire solved as networks; levers, buttons, plates, power block, dust, torches, repeaters, comparators, lamps and pistons; circuits that freeze when partly unloaded; and an extension API for other mods.

**Architecture:** All redstone rules live in a pure Rust crate (`redstone_core`). It has no Weft dependency, reads the world through a `View` trait and is tested with `cargo test` against an in-memory grid. The mod crate (`redstone`) is a thin adapter: it maps Weft blocks, components and tags to core `Cell`s, drives `core::Sim` from `r.world_tick`, and persists pending changes on block entities with saved entity timers. `redstone_api` holds the names and types other mods use. `redstone_tests` is an in-game test mod that runs scenarios on the server and exits with the failure count.

**Tech Stack:** Rust 2024 (rustc ≥ 1.90), `weft_sdk` from the `Weft/` submodule at `f213253`, cdylib mods, no other dependencies.

**Spec:** `docs/superpowers/specs/2026-10-31-redstone-design.md` (read it; this plan argues from it). Engine gaps: `docs/redstone-engine-gaps.md` (G1–G17).

## Global Constraints

- No changes under `Weft/`. Anything missing goes into `docs/redstone-engine-gaps.md` (new entry or evidence on an existing one).
- Build against the submodule exactly: `weft_sdk = { path = "../../Weft/crates/sdk" }` (depth from `mods/<crate>/`); the ABI is hash-checked.
- Mod id `redstone`; every name is `redstone:<path>`.
- Signal range is a per-world config: `choice` over `["16","32","64"]`, default index 0, `.world()`. Max strength 15 / 31 / 63.
- Every wire loses exactly 1 strength per block. Wire only ever gives weak power.
- All changes happen on tick boundaries. Devices react ≥ 1 tick after their input changes.
- Delays in game ticks: torch 1, repeater 1–4, comparator 1, lamp 1 (both ways), stone button 20, wood button 30, plate off 20 after the last entity leaves, piston move 2. Push limit 12.
- No burnout. Dust emits no real light. Lamps do.
- Face order everywhere is Weft's: West, East, Down, Up, North, South (indices 0–5, `opposite = i ^ 1`).
- Determinism: never iterate a `HashMap`/`HashSet` where order can affect results; use `BTreeMap`/`BTreeSet` or sort.
- Commit after every task. The Weft submodule pointer never changes during this plan.

## Review Focus

1. **Redstone in two dimensions at the same coordinates** must behave independently (G6: mods get no dimension id). Test: Task 11, `two_dimensions`.
2. **Wire at the top or bottom build limit** must not freeze. Reading outside the world looks like "unloaded" through the G1 probe. Test: Task 8, `dust_at_height_limit`.
3. **Breaking a device that has a pending change** must drop the change; nothing may be written to that position later. Tests: Task 7, `removed_device_drops_pending`; Task 9, `break_pending_torch`.
4. **Lowering the range setting** on a world with strong dust: strengths above the new maximum clamp on the next solve and are never shown above the maximum. Test: Task 7, `range_lowered_clamps`.
5. **A large wire network toggling every tick** stays correct and doesn't drop updates below the engine's 65,536 budget (G7). Test: Task 8, `long_line_clock` with 2,000 dust.

### Task 3: Cells, the View trait and power rules

**Files:**
- Create: `mods/redstone/core/src/{cell.rs,power_rules.rs,testgrid.rs,devices.rs}` (`devices.rs` holds only the `Kind` enum for now)

**Interfaces:**
- Produces:
  - `pub enum Cell { Unloaded, Air, Block { solid: bool, push: Push }, Wire(Wire), Device(Device) }` (`Clone, PartialEq, Debug`), with `pub enum Push { Move, Break, Never }` (used by pistons in Task 12) and the constructor `pub fn block(solid: bool) -> Cell` (`push` = `Move` if solid else `Break`). Tests always build blocks with `Cell::block(..)`.
  - The `Kind` enum from Task 6 is declared here in `devices.rs` (variants only, no logic) so `Device` can name it.
  - `pub struct Wire { pub kind: u32, pub links: u32, pub powers_blocks: bool, pub strength: u8 }`. `links` is a bitmask of wire kinds it connects with; dust is kind 0 and links `u32::MAX`.
  - `pub struct Device { pub output: [Power; 6], pub connects: u8, pub receives: bool, pub solid: bool, pub kind: Option<Kind> }`. `output[d]` is what it emits into its neighbor on side `d`, with strengths already clamped. `connects` is a bitmask by `Dir::index`. `kind` is `Some` for built-in devices (Task 6) and `None` for extension blocks.
  - `pub trait View { fn cell(&self, p: Pos) -> Cell; }`
  - `pub struct BlockPower { pub strong: u8, pub weak: u8 }`
  - `pub fn block_power(v: &impl View, p: Pos) -> BlockPower`: zero unless `p` is a solid `Block` (or a solid `Device` without its own output toward that side). `strong` = max of neighbor devices' `output[toward p]` with `strong`. `weak` = max of neighbor wires that sit on `p` (wire directly above) or whose shape points into `p` (Task 4's `shape`; until then only "sits on"), where the wire has `powers_blocks`.
  - `pub fn source_into_wire(v: &impl View, p: Pos) -> u8`: for wire at `p`, the max over its 6 neighbors of `device.output[toward p].strength` (strong or weak; sources power adjacent dust directly) and `block_power(neighbor).strong`. Never weak block power.
  - `pub fn inputs(v: &impl View, p: Pos) -> [SidePower; 6]`: per side `d`, neighbor `q = step(p, d)`. A device gives its `output[d.opposite()]` with `direct: true`. A wire gives its strength (weak, `direct: true`) if it sits on `p` or points into `p`. A solid block gives its `strong` power (`strong: true, direct: false`), otherwise its `weak` power (`strong: false, direct: false`).
  - `testgrid::MapGrid` (behind `#[cfg(any(test, feature = "testgrid"))]`): `BTreeMap<Pos, Cell>`, unset positions are `Air`; builder helpers `solid(p)`, `dust(p)`, `put(p, Cell)`, `unloaded(p)`, and `rotated(&self) -> MapGrid` (every position and every `Dir`-indexed array rotated a quarter turn around Y about the origin).

### Task 4: Wire connections and shapes

**Files:**
- Create: `mods/redstone/core/src/wire.rs`
- Modify: `mods/redstone/core/src/power_rules.rs` (weak power from "points into")

**Interfaces:**
- Produces:
  - `#[derive(Clone, Copy, PartialEq, Eq, Debug)] pub enum Link { None, Flat, Up, Down }` (per horizontal side)
  - `pub fn links(v: &impl View, p: Pos, w: &Wire) -> [Link; 4]` (index order = `Dir::HORIZONTAL`). Rules for side `d`, `q = step(p, d)`:
    - `Flat` if `q` is a wire whose kind is linked (`a.links & (1 << b.kind) != 0 && b.links & (1 << a.kind) != 0`; kind ≥ 32 links nothing but itself), or a device with `connects` bit `d.opposite()` set.
    - `Up` if `q` is a solid block, the cell above `p` is not a solid block, and `step(q, Up)` is a linked wire.
    - `Down` if `q` is not solid, not a wire and not a connectable device, the cell `step(q, Down)` is a linked wire, and `q` itself (the cell above that lower wire) is not solid.
    - Steps are symmetric: if `a` links `Up` to `b`, then `b` links `Down` to `a`.
    - `Cell::Unloaded` anywhere in these checks counts as "no link". The network traversal reports it separately (Task 5).
  - `#[derive(Clone, Copy, PartialEq, Eq, Debug)] pub struct Shape { pub sides: [Link; 4], pub points: [bool; 4] }`
  - `pub fn shape(links: [Link; 4]) -> Shape`: no links → `points` all true (cross). Exactly one link on side `d` → points at `d` and `d.opposite()` (line through). Otherwise points exactly where linked. `Up`/`Down` links count as connections.
  - `pub fn points_into(v: &impl View, wire_pos: Pos, target: Pos) -> bool`: target is a horizontal neighbor and the wire's shape points there. A wire always "sits on" `step(wire_pos, Down)`.

### Task 6: Built-in device logic

**Files:**
- Modify: `mods/redstone/core/src/devices.rs` (the `Kind` enum exists since Task 3)

**Interfaces:**
- Produces:
  - ```rust
    #[derive(Clone, Copy, PartialEq, Eq, Debug)]
    pub enum Kind {
        Lever { on: bool, attached: Dir },
        Button { on: bool, attached: Dir, wood: bool },
        Plate { on: bool },                       // attached = Down
        PowerBlock,
        Torch { lit: bool, attached: Dir },       // attached = side of the block it hangs on (Down = standing)
        Repeater { facing: Dir, delay: u8, powered: bool, locked: bool },  // facing = output side; delay 1..=4
        Comparator { facing: Dir, subtract: bool, output: u8 },
        Lamp { lit: bool },
    }
    ```
  - `pub fn outputs(k: Kind, range: Range) -> [Power; 6]`:
    - Lever/Button/Plate when on: `FULL` strong into `attached`, `FULL` weak on the other five sides.
    - PowerBlock: `FULL` weak on all six (direct only; it strong-powers nothing).
    - Torch when lit: `FULL` strong `Up`, `FULL` weak on every side except `attached` and `Up`.
    - Repeater when powered: `FULL` strong toward `facing`. Comparator: `output` strong toward `facing`.
    - Lamp: none.
    - All strengths pass through `range.clamp`.
  - `pub fn connects(k: Kind) -> u8`: Lever/Button/Plate/PowerBlock/Torch all six; Repeater `facing` + `facing.opposite()`; Comparator `facing`, back and both horizontal sides; Lamp 0.

### Task 7: The tick simulation

**Files:**
- Create: `mods/redstone/core/src/sim.rs`

**Interfaces:**
- Consumes: everything above.
- Produces:
  - `pub struct Pending { pub next: Kind, pub remaining: u32 }`
  - ```rust
    pub trait World: View {
        fn range(&self) -> Range;
        fn cube_loaded(&self, cube: [i32; 3]) -> bool;
        fn container(&self, p: Pos) -> Option<u8>;                 // comparator reading at p (Task 10)
        fn write_wire(&mut self, p: Pos, strength: u8, shape: Shape);  // every solved wire; the world shows a level
        fn write_device(&mut self, p: Pos, k: Kind);
        fn notify(&mut self, p: Pos, inputs: [SidePower; 6]);      // extension receivers only
        fn save_pending(&mut self, p: Pos, pending: Option<(Pending, bool /*frozen*/)>);
    }
    ```
  - `pub struct Sim { /* pending: BTreeMap<Pos, PendingEntry{pending, cubes, frozen}>, dirty: BTreeSet<Pos>, last_inputs: BTreeMap<Pos, [SidePower;6]> */ }`
  - `impl Sim { pub fn touch(&mut self, p: Pos); pub fn schedule(&mut self, p: Pos, pending: Pending); pub fn forget(&mut self, p: Pos); pub fn tick(&mut self, w: &mut impl World); pub fn has_pending(&self, p: Pos) -> bool; }`

  `tick` order (spec §6):
  1. **Freeze check:** for each pending entry, `frozen = !entry.cubes.iter().all(|c| w.cube_loaded(*c))`. A newly frozen entry calls `save_pending(p, Some((pending, true)))`. A frozen entry is not counted down.
  2. **Count down:** decrement `remaining` on unfrozen entries. Collect those at 0. Drop any whose cell is no longer a device of the same variant (`forget` semantics). Apply all with `write_device`, then `touch` each and its 6 neighbors. Call `save_pending(p, None)` for each applied.
  3. **Solve:** from `dirty`, collect the wires to recompute: dirty wires, wires next to a dirty position, and wires next to a solid block that is next to a dirty position. Group them into networks (each network once). An `incomplete` network is skipped (frozen): its start position goes into `frozen_dirty: BTreeMap<Pos, u32>` with a countdown of 20 and is re-added to `dirty` when the countdown reaches 0. That way a frozen circuit costs one traversal per 20 ticks, not one per tick (spec §7.1). Otherwise `solve`.
  4. **Write:** call `write_wire` once for every wire of every solved network; the world skips writes that change nothing it shows. (Amended 2026-10-31: worlds don't store strength, spec §8.)
  5. **React:** candidates are every device a solved network read (`Network::devices`) and devices around dirty positions. For each candidate without a pending entry, compute `inputs` on the `Solved` view (strengths solved this tick, other networks solved on demand, incomplete ones freeze the candidate). Built-ins: `react(..)` → `schedule(p, Pending{next, remaining: delay})` with `cubes` = union of the cubes of networks touching it (at least its own cube). Extension receivers (`kind: None, receives: true`): `notify` if inputs differ from `last_inputs`.
  6. Clear `dirty`.

  A device with a pending entry ignores new reactions until it fires (spec: pulse stretching, one pending change per device). `schedule` also calls `save_pending(p, Some((pending, false)))`.
